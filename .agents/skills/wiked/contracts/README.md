# Contracts Interface

`wiki-structure.schema.json` is Wiked's versioned, generic metacontract. It validates a consumer's `wiki/wiki-structure.yaml` before any wiki page is processed. Contract migration is always explicit; an unsupported `contract_version` or a methodology version with a different major or newer requirement is rejected rather than rewritten. `navigation.authoring_file` optionally identifies one root Markdown reference for instance-local human-review criteria; it is not operational evidence or a second machine-readable contract.

The schema defines only portable structure. Instance language, approved initial purpose, audience, scope, resolved context terms, naming pattern, trunks, depth, page types, states, fields, sections, optional structured record collections, provenance, asset policy, diagram sets, tracking, and rule severities remain consumer configuration. When `structured_sections` is configured, `rules.structured_sections` sets one severity for that diagnostic family; instances that do not use the optional capability need no such rule. The validator checks that setup materializes the approved initial values without inventing domain pages. External links and bare URLs are informational and are not validation inputs.

Human qualification and local ingestion paths are deliberately outside the contract. A participating human confirms qualification for each governed session and objective. Wiked uses the fixed `raw/` and `raw/archive/` workflow for local ingestion material, while the consumer's humans decide whether those files are persisted in Git.

`structured_sections` is optional. A configured collection applies to named page types and declares a section, record cardinality, and fields. Its section contains immediate subheadings as records; each record contains `- **Field:** value` items or a field followed by a nested value list. Fields declare permitted `value_types` (`text`, `page`, or both), value cardinality, an optional explicit `empty_value`, and optional `disjoint_with` page fields. A `page` value is a relative Markdown link whose label exactly matches the destination page H1. Sections without this configuration remain free-form Markdown.
