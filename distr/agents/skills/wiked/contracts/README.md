# Contracts Interface

`wiki-structure.schema.json` is Wiked's versioned, generic metacontract. It validates a consumer's `wiki/wiki-structure.yaml` before any wiki page is processed. Contract migration is always explicit; an unsupported `contract_version` or a methodology version with a different major or newer requirement is rejected rather than rewritten. `navigation.authoring_file` optionally identifies one root Markdown reference for instance-local human-review criteria; it is not operational evidence or a second machine-readable contract.

The schema defines only portable structure. Instance language, approved initial purpose, audience, scope, resolved context terms, naming pattern, trunks, depth, page types, states, fields, sections, optional structured record collections, provenance, asset policy, diagram sets, tracking, and rule severities remain consumer configuration. When `structured_sections` is configured, `rules.structured_sections` sets one severity for that diagnostic family; instances that do not use the optional capability need no such rule. The validator checks that setup materializes the approved initial values without inventing domain pages. External links and bare URLs are informational outside typed canonical-reference fields and intent-map destination entries; those require local canonical links.

Human qualification and local ingestion paths are deliberately outside the contract. A participating human confirms qualification for each governed session and objective. Wiked uses the fixed `raw/` and `raw/archive/` workflow for local ingestion material, while the consumer's humans decide whether those files are persisted in Git.

`structured_sections` is optional. A configured collection applies to named page types and declares a section, record cardinality, and fields. Its section contains immediate subheadings as records; each record contains `- **Field:** value` items or a field followed by a nested value list. Fields declare permitted `value_types` (`text`, `page`, or both), value cardinality, an optional explicit `empty_value`, and optional `disjoint_with` page fields. A `page` value is a relative Markdown link whose label exactly matches the destination page H1. Sections without this configuration remain free-form Markdown.

`navigation.intent_map` optionally names a distinct Markdown file at the wiki root; it is not the literal filename. For example, `intent_map: routes.md` identifies `wiki/routes.md`. It requires `methodology_version` 1.5.0 or newer and retains `contract_version: 1.0`. New runtimes preserve contracts without this capability; older schemas reject the new key. Adoption and migration require explicit authorization, never automatic rewriting.

The consumer owns this human-readable map and its domain vocabulary. The root index links to it exactly once. Its common format is an H1, optional coverage introduction, and H2 intents with direct `- [Canonical title](relative.md) - Guidance.` items, in the instance language. Each intent needs at least one destination and nonempty guidance; no frontmatter or operational role is allowed. Destinations are canonical operational pages or indexes, with exact H1 labels and optional existing fragments, not sources, ingestion, governance, configuration, or instructions. Shared and cross-trunk destinations are allowed between intents, not duplicates within one intent. Index restrictions remain unchanged. See `../guides/modeling.md` for authoring boundaries and `../guides/query.md` for selective loading.

`page_types.<type>.external_authority` optionally marks a page type whose authority lies outside the wiki. It declares a nonempty `notice`, literal text in the instance language, and `link: required` or `link: optional`. Declaring it requires `methodology_version` 1.8.0 or newer and `rules.external_authority`, which sets one severity for its `external-authority.*` diagnostics; `contract_version` remains 1.0. On every page of that type, the first block after the H1 is a quotation whose first paragraph contains the notice literally, ignoring inline formatting and comparing collapsed whitespace. Every link in that quotation, including autolinks, is an absolute `http` or `https` URL; `required` demands at least one. The link is independent of provenance records and need not match any source record. The validator does not compare external content or decide correctness, currency, completeness, reproduction rights, or responsibility.

Map form and destination eligibility use `rules.navigation`; ordinary link existence, boundary, and fragment diagnostics use `rules.reference`. Human curation, not the schema or runtime, establishes relevance and support for guidance. The map is navigation, never operational evidence or a guarantee of completeness.
